inventó un isotipo. No se crearon SVG de PPF HOUSE ni se reutilizaron gráficos

los SVG Ferraro retenidos pero no usados por la interfaz.

Entorno de pruebas
Las pruebas que crean o borran datos se ejecutaron exclusivamente en una nueva
instancia local Prisma Dev/PGlite, con valores de conexión limitados al proceso.
No se editaron archivos .env, esquema Prisma, dependencias ni migraciones.
Se preparó el esquema en la base desechable mediante db push; al detectar que no
incluye los CHECK SQL manuales, se restauró el CHECK salarial ya existente solo
en esa base temporal. No se ejecutaron migraciones sobre Railway.
La primera suite tuvo 74/74 unitarios y 75/78 de integración: dos errores 25001
(SET TRANSACTION ISOLATION LEVEL must be called before any query) en borrado,
y un fallo por ausencia del CHECK salarial en la base temporal. Este último
se reprodujo con una copia del commit original. Los dos casos de borrado
pasaron al ejecutarse por separado contra el commit original; no se atribuyen
con certeza a esta adaptación y no se modificó su lógica.

Referencias heredadas conservadas deliberadamente
- public/brand/ferraro-*.svg: referencias técnicas históricas, sin uso activo.
- docs/brand y documentación histórica: conservadas como antecedentes Ferraro.
- package.json name=ferraro-manager: identificador técnico; sin cambios de deps.
- ferraro:sidebar-collapsed y ferraro:sidebar-change: compatibilidad de preferencias.
- ferraro_portal: cookie conservada para no alterar sesiones del portal.
- prefijo ferraro_ de prepared statements: identificador interno sin efecto visual.
- Fixtures, emails y datos de prueba históricos: no son identidad institucional.
En src solo quedan referencias Ferraro en los identificadores técnicos anteriores.
DetailHeader, funciones *Detail y Detailing son términos técnicos o del servicio,
no referencias institucionales a Ferraro Detail.
